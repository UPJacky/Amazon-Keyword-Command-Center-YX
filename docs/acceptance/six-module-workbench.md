## 设计决定

已读取原始 `DESIGN-airtable.md`，version=`alpha`，SHA-256=`1d225e511213044d3c705bde50265ad010932bfd8a15740a144dd4f480128889`。它描述 Airtable 营销页，黑CTA/纯白hero/96px大段距不适配本次密集数据工作台。按用户参考图明确覆盖这些视觉项，不静默修改原参考文件。

采用深蓝与皇家蓝、浅灰蓝底、白色卡片；状态颜色只用于业务标记。每个业务功能独立 HTML 和 JS，共享样式、导航、加载格式和登录门禁；不复制六套认证逻辑、不把整个页面套进 iframe。拆文件有助于维护，不等于安全隔离；正式权限必须由服务端/RLS执行。

两份中文指南仅作理解和验收参考。其中的暂停节奏、对象公共读和供应商示例不覆盖用户最新持续执行要求与本项目私有报告架构。

## 验证与交付边界

页面只读取经过审计的本地演示产物；真实模式保持拒绝回退到演示数据。公开 Pages 的演示 JSON 本来就是公开数据，演示登录门禁不能作为真实 RLS 证据。

本轮不调用付费 Provider、不改密钥和后端权限、不部署服务器。页面改版不能关闭真实上传→Worker→私有报告的生产 Gate。应先验收六模块交互，再分任务补齐上表的数据/规则链路，不能把本地测试全部通过描述成业务 V1 完成。

## P7 视觉复核补充

共享 `frontend/styles.css` 继续作为六个独立报告页的唯一视觉基线：浅灰蓝画布、深蓝到皇家蓝渐变 Hero、白色摘要卡、左侧模块导航和宽表横向滚动。P7 仅补充层级与状态可读性：Hero 增加低干扰圆环背景和阴影，当前模块导航使用蓝色内侧强调线，表格行提供轻量悬停反馈，广告实体诊断卡明确区分“可判断”和“数据待补”。
