钥匙版本说明（给你，AI）：Supabase 新版钥匙 sb_publishable_ = 本计划里一切写 anon key 的地方，sb_secret_ = 一切写 service_role 的地方，功能与用法一一对应；老版 JWT 格式钥匙 2026 年底弃用，新项目一律用新版，不要混用。

2. 告诉用户去 Storage 建一个什么名字的私有收件箱桶，配套 Storage 门禁规则（登录用户只能传自己名下目录、只能读自己传的文件）一并跑。收件箱路径从现在定死：{user_id}/{任务id}.{实际后缀}（后缀跟用户实际上传的文件走，.xlsx 或 .csv），写进进度记录，后面上传、取件、直验三处都按它，不许各写各的。任务 id 谁生成、什么顺序，也从现在定死：**id 由前端用 crypto.randomUUID() 生成，先传文件到收件箱，传成功再插任务行（状态"待处理"），插行成功才算提交成功**。理由要记住：上传那一刻就要用 id 拼路径；而 RLS 只给登录用户 INSERT+SELECT（没有 UPDATE），"先插行拿数据库生成的 id、再传文件"的路子一旦上传失败，会留下一条有行没文件的待处理任务且用户改不了状态——反过来只会留一个工人永远不碰的孤儿文件，无害。建表 SQL 里的 default gen_random_uuid() 留着当兜底，但前端每次都显式传 id。任务行必须把完整文件路径写进"报表文件路径"字段，工人取件只认这个字段，不自己拼路径；

4. 做一轮测试：注册一个测试账号（这个账号和它的 user_id 记进进度记录，后面直验还要用它）写一条任务并读回；用 service_role 把它标记"已完成"；验证未登录读任务表被拒。三个结果发用户。

验收：Table Editor 见测试任务且状态"已完成"；"未登录被拒"有证据。

西柚怎么接（写给你，AI）：西柚找词是一个远程 MCP 服务，服务器可以直接 HTTP 调用，地址：
https://mcp.xydc.com/mcp?mcp_token=（密钥库里的西柚 Token）

再问用户两道思考题，答案记进本计划再动手：

执行细则，把工人处理逻辑写完整，五步——
1. 调西柚：反查该 ASIN 的关键词，按流量取前 200 个；
2. 逐词补齐：月搜索量、投放难度、建议竞价、ABA 近 13 周周搜趋势、该词点击前三的 ASIN/点击占比/主图、用户的 ASIN 和最强竞对在该词下的自然位（最强竞对默认=该词点击占比最高的非自己 ASIN，用户可改）。控节奏加间隔别并发轰接口；单词失败重试不超过 2 次，全部失败标"数据缺失"继续往下，不卡死整个任务；
3. 解析广告报表（取件按任务表"报表文件路径"字段去收件箱下载，不自己拼路径；.xlsx/.csv 都要认）：按表头识别 搜索词/曝光/点击/花费/订单 列（列名对不上就把表头原样打出来给用户对），逐词聚合出单量/花费/ACOS，没投过的词标"无投放"；
4. 按用户的判断规矩把每个词的数据喂豆包（.env 里的 key 和模型名），生成一句打法判断，规矩之外不自由发挥；
5. 渲染报告 HTML（排序按用户定的），文件名用一长串随机字符（不可猜=半私有），上传 OSS 本工具 reports/ 目录，Content-Type 设 text/html; charset=utf-8，对象单独设公共读，把永久公开链接连同状态"已完成"写回任务表——链接永久有效，不存在过期问题。处理完把收件箱里的报表原件删掉（省免费额度）。
要求可重跑：同一任务重跑不产生错乱数据。200 词全量一般要跑 10-30 分钟，属正常，教用户在 pm2 logs 看进度，别当卡死去重启。改完只重启本工具的 worker 进程。

后台直验（前台还没建，用管理通道验）：把阶段 0 记录的虚拟报表按定死路径放进收件箱（用阶段 3 那个测试账号的 user_id），用 service_role 插一条 B09V366BDY 的任务→工人跑完→把报告公开链接发用户：浏览器直接打开会是下载，下载后双击打开看内容（原因同阶段 4，正式版前台会在线渲染）。

验收：用户看到作战总表，四类数据列齐全（热度/竞争格局/自己广告实绩/打法建议）；随便抽一个词的月搜索量跟西柚后台对得上；建议列看得出是按用户规矩判的。

三个页面的功能底线（样式随用户定，功能缺一不可）：
- 登录页（index，主域名直开）：登录/注册切换；报错说人话（"密码不对"而不是英文错误码）；登录成功跳工具页；已登录访问自动放行。
- 工具页（tool/）：ASIN 输入框带格式校验（10 位、B0 开头，不合格当场提示）；报表上传限 .xlsx/.csv、限制大小（超限提示）；提交流程按阶段 3 定死的顺序：前端 crypto.randomUUID() 生成任务 id → 按定死路径先传文件 → 传成功再插任务行（状态"待处理"，路径写进"报表文件路径"字段），插行成功才算提交成功；提交按钮防重复点击，提交成功有明确反馈；我的任务列表（提交时间/ASIN/状态/查看报告按钮），每 30 秒自动刷新+手动刷新按钮；失败的任务把"失败原因"显示出来（对应任务表字段）；页头有退出登录。
- 报告页（report/）：网址带任务号（如 report/?task=xxx）；加载中有提示；fetch 取回报告在线渲染；有"返回工具页"入口。

作战总表的呈现底线（列什么用户定过了，这里管"读得清"）：
- 一行一词，列=四类数据（热度/竞争格局/自己广告实绩/打法建议）拆出的数据项；
- 宽表格必须固定列宽+在容器内横向滚动，绝不允许挤压换行糊成一团——手机上左右划着看，也比挤成竖条强；
- 趋势可以画迷你折线也可以只列数字，主图缩略图加载失败要有占位，别一排裂图。

执行细则：
1. 三个独立页面，放 交付/前台/：仓库或托管的根目录放 index.html（登录页——主域名直接打开的就是它），tool/、report/ 两个子目录放工具页和报告页（三个不同网址）。登录页接中转台登录注册，未登录访问任何页一律跳回；工具页=ASIN 输入+报表上传到收件箱（按定死路径）+我的任务列表（状态可刷新）；报告页=用 fetch 把任务表里的报告公开链接取回来在线渲染（iframe srcdoc 或容器注入），绝不直接跳转 OSS 链接（会变下载、还裸露桶地址）。只用 anon key。supabase-js 这类前端库文件直接下载进前台目录本地引用，别引国内不稳的外链 CDN。先在用户本地浏览器过目，确认再部署；
2. 按路线部署：
   - 甲线·自己服务器：装 nginx 出静态页，安全组只放行 80/443，指导用户解析 A 记录指服务器 IP；
   - 甲线·OSS / OSS+CDN：另建一个独立的前台托管桶（开静态网站托管，桶内就是前台文件）——绝不复用私有文件柜桶，更不准把文件柜桶改公共读；指导绑定自定义域名和解析，选 CDN 的加配 CDN 并把 HTTPS 挂 CDN 上；
   - 乙线·GitHub Pages：前台仓库推上去，Settings→Pages 选根目录发布；自定义域名分两步——先在 Pages 设置里填用户的域名等 DNS 检查，解析这边：裸域加 4 条 A 记录（185.199.108.153 / 109.153 / 110.153 / 111.153），www 加 CNAME 指 用户名.github.io；Enforce HTTPS 要等 GitHub 把证书签出来才能勾，灰着就是再等等；
3. HTTPS：甲线指导用户在阿里云"数字证书管理服务"申请免费证书（个人每年 20 张、一张管 3 个月）并部署；证书到期日写进进度记录，并给工人加一个每日自查：证书剩余不足 14 天就在日志和任务表里报警；
4. 甲线：把用户的备案号加到三个页面页脚，链接 https://beian.miit.gov.cn；
5. 部署前最后一次密钥扫描：前台文件里只有 anon key，没有 service_role、SSH、OSS、豆包、西柚的任何钥匙。

乙线加练（建议做，练完以后所有工具都能用；对应第 7 章附）：
1. 服务器本项目文件夹写 API 服务，监听一个 10000 以上高位端口（你挑一个报给用户），绝不监听 80/443，绝不输出网页内容；
2. 指导用户加子域名解析（A 记录指服务器 IP），为子域名申请免费证书部署到 API 上（到期日进度+工人自查报警同上）；

5. API 用 pm2 单独起进程（名字带 api），跟 worker 分开。

验收：用户手机打开自己的域名见登录页（https 小锁；甲线页脚有备案号）；乙线加练的，未登录调 API 被拒。

- 域名怎么解析？——去买域名的控制台找"域名解析/DNS 设置"加一条记录；加什么类型填什么值按他所在阶段和路线给出，填完等几分钟到几小时生效。

- 报 permission denied？——RLS 门禁规则问题，重给 SQL 跑一遍。
- 登录转圈/工人日志全是网络超时？——国内到 supabase.co 偶发抽风，先 curl 测连通性，等一等或换网络再试，别急着改代码。
